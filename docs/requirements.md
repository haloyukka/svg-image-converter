# SVG Image Converter 要件定義書

- 版: 1.0 / 2026-10-17（日本時間）
- 利用者: 本人。第三者がアクセスできる公開URLを許容する。
- 成果物: ビルド不要のWebツール、要件定義書、AI実装依頼プロンプト、技術検証結果をZIPで納品。
- **状態: 要求を確定した検証版。全機能の完成・受入完了を意味しない。** 未達要求は削除せず、下記のリリース阻害課題として管理する。

## 1. 目的・前提

SVGファイルまたはSVGコードを、目的に応じた静止画・アニメーション画像へ一括変換する。サーバーへの入力ファイル送信、アカウント登録、バックエンド、ビルド工程を設けない。GitHub PagesにHTML/CSS/JavaScriptを配置して利用する。オンライン利用のみを対象とし、PWA・オフライン対応は対象外。

「サーバーへ送信しない」は変換処理に関する条件であり、サイト閲覧、許可した外部参照、CDN通信まで禁止する意味ではない。外部通信にSVG本文を付加しない。第三者ライブラリはCDN/WASMを含め利用可。現検証版は依存なし。

## 3. 入力・SVG互換性

ファイル名の拡張子だけを信用せずXMLとして解析する。ルートはSVG名前空間のsvg必須。width/heightがなければ有効なviewBoxから取得する。現実装は数値/px以外の単位を未対応として中止する。負数・0・不正XMLも中止する。DOCTYPE/ENTITY/XML外部スタイルシート指示は禁止。

将来の完成版はSMIL・CSS・許可したJavaScriptを対象とする。未対応の要素・機能が判明したファイルは中止し、黙って削除して成功扱いにしない。現実装はscript、イベント属性、foreignObject、SMIL、外部参照、CSS at-rule/アニメーション/エスケープ等を保守的に拒否する。未知構文やフォント差による描画差まで完全検知できるとは保証しない。

SVG内のviewBox / preserveAspectRatioは元SVGの描画に従い、その描画を出力枠にcontain/cover/stretchで配置する。縦横比固定の寸法入力補助は将来改善項目だが、fitによる比率維持は必須。

### 外部参照の完成条件

読み込む前にURL・種類・許可対象を表示し、ファイルごとに確認を取る。許可後、CORSで取得可能な画像・フォントをローカルへ取得し、SVG内に埋め込んでから描画する。credentialsはomit、タイムアウト・件数・容量上限を設ける。拒否、CORSエラー、取得失敗は理由を表示して中止。外部use、CSS importの再帰参照や循環は別途制限する。PNG等に見せかけたSVGは受け付けない。CDN依存とユーザー素材への外部参照の許可は分離する。

## 4. 出力・背景・命名

PNGは透過を維持。JPEG/BMPは透過部分を白で合成する。WebP/AVIF/TIFFは対応するアルファを利用。GIFは二値透過・256色であり、半透明や原色再現に限界がある。これらは形式固有の仕様としてプレビューと説明で知らせる。原SVGとバイト/色が完全一致する要件とはしない。TIFFは単一ページ。ICOは複数の正方形画像を1ファイルに格納し、256pxはディレクトリ上0で表す。

用途別サイズは固定プリセット値。SNSサービスの最新推奨寸法を保証しない。OGP1200×630、ヘッダー1500×500等を初期収録しJSONで独自設定を移せる。

背景画像はPNG/JPEG/WebP。JSONにはバイナリを含めず名前のみを記録し、再読込時に再選択を案内する。現実装では背景画像はセッション共通。**ファイルごとに異なる背景画像の保持は未達**であり、完成版では共通設定と上書きの両方に対応させる。

命名例: `{name}_{width}x{height}.{ext}`。不正パス文字を置換し、同名結果は連番。ICO複数寸法時の命名は代表寸法またはsizesトークン追加を検討する（現実装は一般出力枠の寸法）。コード貼付はpasted-N.svgを仮名とする。

## 5. 画面・操作フロー

1. SVG追加: ファイル/ドロップ/コード。検査失敗をその場で通知。
2. 設定: 対象を全体または各SVGに切替。サイズ、fit、背景、形式、ICO、命名を指定。
3. 比較: 元SVGと設定反映PNGプレビュー、出力後は選択形式と容量を比較。
4. 変換: ファイル単位で逐次処理。進捗、キャンセル、再試行。
5. 保存: 個別/ZIP/PNGコピー。形式非対応なら代替のダウンロードを案内。
6. 履歴: 名前・設定・成否・時刻のみローカル保存。削除・上限変更。

共通設定は個別上書きのない入力に適用。JSONはschemaVersionを検査し、不正値で現在設定を破壊しない。個別設定はファイル名で再適用するため、同名入力の識別精度は改善課題（内容ハッシュ推奨）。

専用キー: Ctrl/Command+Enterで変換、Escapeで中止、Ctrl/Command+Shift+SでZIP。タッチでホバー不要。標準フォームにラベル、操作ボタンにフォーカス可視化、進捗はrole=statusで通知。詳細なキーボード/スクリーンリーダー試験は受入時に実施する。

## 6. 保存・プライバシー

入力本文、背景画像、結果画像はメモリのみ。ページを閉じると破棄。localStorageには履歴設定・上限・時刻・ファイル名・変換設定・成否のみを保存する。プリセットはユーザー操作によるJSON書出/読込だけ。フォントファイルアップロードは対象外。履歴保存不可でも変換を継続し原因を通知する。アクセス解析・広告・アップロードAPIは導入しない。

## 7. 非機能・上限

以下の数値は検証版の暫定値であり、すべての端末で処理成功する保証値ではない。

|項目|暫定設計値|
|---|---|
|SVG単体 / 入力合計|10MiB / 64MiB|
|背景画像|20MiB|
|プリセットJSON|1MiB|
|出力辺長|最大16384px|
|1画像画素数|min(3200万, deviceMemory×400万)。APIなしは4GBと仮定|
|並列数|1。固定最大件数ではなく逐次処理|
|結果保持予算|256MiB（結果＋比較用PNGの保守的合算）|
|ZIP|結果合計512MiB・65535項目以下。非ZIP64|
|履歴|初期100件、設定1〜10000件|

完成条件には入力総容量・結果総容量のメモリ予算、メモリ不足時の復旧、アニメーションの総フレーム予算、WorkerによるUI応答性、即時キャンセルを含める。現検証版の逐次処理だけでは端末負荷制御の要求を満たさない。出力画質、サイズ、FPSを無断で下げない。失敗を再試行する際の既存成功結果の二重保存は改善課題。

## 8. 技術構成・候補

現構成: index.html / css/style.css / js/app.js / js/svg.js / js/encoders.js。ES Modules、DOMParser、Canvas、Blob、Clipboard、localStorage。純JavaScript、ビルド不要。

|領域|候補・判断|検証の焦点|

|JS隔離|sandbox iframe、通信制限、postMessage|許可前実行ゼロ、親DOM/storage操作不可、ネットワーク権限|
|AVIF|ブラウザネイティブ、WASM単一スレッドエンコーダー候補|型/バイト確認、メモリ、Pages配信、追加ファイルライセンス|
|GIF動画|gifenc等の候補を調査|透過、パレット、ループ、Worker|
|APNG|UPNG.js等の候補を調査|フレーム差分、delay、PNG拡張チャンク|

候補名は採用・動作保証ではない。採用前に公式ソース、ライセンス、再配布条件、保守状況、必要ヘッダー、CDN障害時挙動、バージョン固定を確認する。GitHub Pagesのパス配下配置を前提に相対URLを使う。SharedArrayBuffer必須構成に依存せず、単一スレッドWASMを優先検証する。

## 9. アニメーション・JSのリリース阻害課題

任意JavaScriptは実時間、乱数、非同期処理、ネットワーク、ユーザー操作に依存し得る。したがって任意の時刻へ常に正確にシークできる保証はできない。再現できる制御契約/制約を定め、再現不可なら中止する。サンプルが静止画のみなので動画対応の受入試験は別サンプルで必要。

|課題|合格条件|
|---|---|
|G01 時間制御|SMIL/CSS/JSそれぞれで同一時刻のフレームを再生成し一致。開始/終了/FPSからフレーム数が決定される|
|G02 JS隔離|許可前は一切実行せず、許可後も親DOM・localStorage・任意ネットワーク・ポップアップへアクセス不可。タイムアウトで停止|
|G03 動画符号化|GIF/WebP/APNGで幅高さ・フレーム数・遅延・ループ・透過を独立デコーダーで確認|
|G04 再現不可検出|制御不可のサンプルをエラーにし、原SVGの一部を黙って捨てない|
|G05 外部参照|URL単位許可・CORS成功/失敗・拒否・循環/容量超過を試験し、通信前確認を証明|
|G06 AVIF|少なくとも1つの対象ブラウザで有効なAVIFを生成。非対応環境では理由を添えて無効化|
|G07 負荷/中止|大きな入力/長時間動画でもUI応答、予算超過の事前停止、キャンセル後の資源解放|
|G08 実機行列|Windows Chrome/Edge/Firefox、Mac Safari/Chrome/Firefox、Android Chrome/Firefox、iPhone Safari/Chrome/Firefoxで該当機能を検証|

これらは初期版要求の一部。段階リリースへの要件変更は行っていない。現検証版は完成版として公開・受入判定しない。

## 10. 受入条件

- AT01: 同梱5SVGを読み込み、元サイズPNGを生成。880×500 / 880×560 / 880×440 / 880×400 / 880×500。
- AT02: PNG/JPEG/WebP/GIF/BMP/TIFF/ICO/AVIFをバイナリ識別し、拡張子だけ変更したPNGでない。非対応AVIF等は事前無効。
- AT03: 透過PNG、JPEG白合成、背景画像、contain/cover/stretchを画像比較。
- AT04: 複数入力×複数形式、同名連番、ZIP3配置を展開してCRCと日本語名確認。
- AT05: 個別上書きと共通設定、JSON round-trip、異常JSON時状態維持。
- AT06: 未対応SVG、script、イベント、外部参照を実行前停止。成功と表示しない。
- AT07: 1件失敗して他を続行、キャンセル、失敗分のみ再試行、資源解放。
- AT08: 保存API不可、ストレージ拒否、寸法/容量超過を適切に表示。
- AT09: 日英、OS色、320px以上の画面、キーボード、読み上げを実機確認。
- AT10: 履歴に画像本文がないこと、100件初期上限、上限変更/個別削除/全削除を確認。
- AT11: G01〜G08をすべて合格。未対応環境の機能は理由と推奨環境を表示。
